* Evil Visual Block in Windows Terminal

=C-v= enters Evil Visual Block selection from Normal state. Windows Terminal
must forward this key instead of using it to paste from the clipboard.
In Windows Terminal's =settings.json=, use these entries in =keybindings=:

#+begin_src json
{ "id": null, "keys": "ctrl+v" },
{ "id": "Terminal.PasteFromClipboard", "keys": "ctrl+shift+v" }
#+end_src

=Ctrl+Shift+V= still pastes from the terminal clipboard. If =C-v= runs
=xterm-paste=, the terminal is sending bracketed clipboard text instead of
the key; rebinding Evil cannot fix that interception.

* Visual line wrapping

All editing buffers, including code, Org, Markdown, scratch buffers, and files
without an extension (including piped input), use the built-in =visual-line-mode=
with character-based wrapping at the window edge, without inserting newline
characters. Words may be split between visual rows.
=visual-wrap-prefix-mode= preserves contextual indentation on continuation
rows, such as inside lists.

Terminal Emacs displays the Unicode rightwards arrow with hook (=U+21AA=) at
the right edge of each continued segment. The buffer-local display table's
=wrap= slot supplies this indicator, without plugins or graphical fringes.
Line numbers count logical file lines rather than visual rows, with the absolute
number shown on the current logical line; continuation rows do not acquire new
line numbers.

Wrapping is applied after every major-mode change and to existing buffers when
the configuration is loaded. Minibuffers are not changed during that reload.
Neither Auto Fill nor paragraph reformatting is enabled, and wrapping does not
modify file content.

* Filling text to the current window

In text buffers, including Org and Markdown, =M-q= (=fill-paragraph=) and Evil's
=gq= use the selected window's usable width minus two columns. The width is
calculated when the command runs, accounting for line-number space and the
continuation indicator. Resizing, splitting windows, and connecting a new
=emacsclient= frame require no configuration reload.

The daemon only installs the command advice at startup; it does not calculate a
terminal width then. =fill-column= is bound temporarily for each filling command,
so two windows showing the same buffer can use different widths without changing
that buffer's saved setting. Programming buffers keep their existing fill width.

These explicit filling commands insert real newline characters and modify the
buffer. Visual wrapping remains display-only, and Auto Fill is not enabled.

* Code folding

Origami is enabled in programming modes and =vimrc-mode=. The original
=triple-braces= configuration is restored: regions delimited by ={{{= and
=}}}= are folded, including nested regions and markers in comments.
All marker folds start closed when a programming buffer is opened.
Ordinary comment lines and unmarked code are not folded.

Lua files use =lua-mode=; Vimscript files (=.vim= and =.vimrc=) use
=vimrc-mode=. Missing packages are installed from the local ELPA mirror.

In Evil Normal state, =TAB= or =za= toggles a code fold, =zc= closes it,
=zo= opens it, =zM= closes all folds, and =zR= opens all folds.
Org and text buffers retain their existing folding behavior.

* Snippets

YASnippet is installed from the local ELPA mirror and enabled in programming,
text (including Org), and configuration buffers, but not terminal buffers.
Personal snippets are loaded from =emacs/snippets/= in this repository,
also available as =~/.emacs.d/snippets/= after deployment. Subdirectories
are named after major modes. A snippet's =# key:= header defines its
abbreviation; without that header, its filename supplies the key.
For example, =js-mode/log= expands =log= and =org-mode/el.snippet= expands =el=.

In Evil Normal state:

- =SPC i e=: expand the snippet key at the cursor and enter Insert state.
- =SPC i i=: select and insert a snippet, then enter Insert state.
- =SPC i n=: create a snippet.
- =SPC i v=: visit a snippet's source.
- =SPC i d=: open the personal snippets directory in Dired.

In Evil Insert state:

- =TAB=: expand the snippet key immediately before point. If no snippet
  matches, run the existing TAB command (such as indentation or Org cycling).
- Inside an active snippet, =TAB= and =S-TAB= move between fields.

Normal-state TAB bindings remain unchanged. No additional plugin is needed.
Files ending in =.snippet= use =snippet-mode=.

* Local thin MELPA mirror
Run =make= from the =emacs/= directory to regenerate the mirror from installed
Emacs packages. The =ninrod/thin-melpa-mirror= repository must already be cloned
by the dotfiles installer. The script writes the mirror there and saves each
run's output in =emacs/scripts/logs/[YYYY-MM-DD-HH-MM-SS]-thin-elpa-mirror.log=.
