* Multi-step workflows

** Save a position and return to it

The Evil marker =z= stores one position; setting it again replaces the
previous position. This is separate from Emacs's mark ring (=g TAB=).

| Key | Command / effect                                                                  |
|-----|-----------------------------------------------------------------------------------|
| s m | Save the current position in marker =z= (=ninrod/evil-set-marker-z=).             |
| g m | Jump to marker =z= and center the destination line (=ninrod/evil-goto-marker-z=). |

** Record a macro and apply it to selected lines

Record the editing operation once, then select the target lines. The
custom replay command uses the last Visual selection's range, not just the
current cursor position.

|  Key             | Command / effect                                                          |
|                  |                                                                           |
|  m m             | Record a macro in register =z= (=ninrod/evil-record-macro-z=).            |
|  m m             | Invoke the recording command again to stop recording.                     |
|  V, then motions | Select the lines on which to replay the macro.                            |
|  m a             | Run ='<,'>norm @z= over the selected line range (=ninrod/apply-z-macro=). |
|  Q               | Invoke =evil-record-macro= with an explicitly chosen register             |

** Create, visit, and remove a bookmark

| Key   | Command / effect                                    |
|-------|-----------------------------------------------------|
| s b   | Save a named bookmark (=bookmark-set=).             |
| s SPC | Choose a bookmark and jump to it (=bookmark-jump=). |
| s -   | Delete a bookmark (=bookmark-delete=).              |

** Narrow the editing scope and restore it

Choose the narrowing operation appropriate to the buffer. Rectangular
narrowing has its own matching restore command.

|  Key | Command / effect                                                      |
|------|-----------------------------------------------------------------------|
|  s n | Narrow a rectangular region (=rect-ext-narrow=).                      |
|  s w | Undo rectangular narrowing (=rect-ext-widen=).                        |
|  , n | Restrict the buffer to the current subtree (=org-narrow-to-subtree=). |
|  m w | Remove buffer narrowing (=widen=).                                    |

*** Edit a rectangle with rect-ext

The configured package [[https://github.com/noctuid/rect-ext.el][noctuid/rect-ext.el]] provides two ways to edit
only a rectangular selection: an Evil Ex =B= command, similar to Vim's
vis.vim =:B= or Veep's =:P=, and a separate buffer for longer edits.
These workflows are for rectangles, not arbitrary characterwise regions.

**** Apply an Evil Ex command to the rectangle

1. In Evil Normal state, press =C-v= and use motions to select a rectangle.
2. Press =:= and replace the automatically inserted range with the
   backtick range shown below. Backticks preserve character positions;
   apostrophes address whole lines and can lose the rectangle's columns.
3. Enter =B= followed by the Ex command, then press =RET=.

Replace every occurrence of =foo= only within the selected rectangle:

#+begin_src vim
:`<,`>B s/foo/bar/g
#+end_src

Sort only the selected column:

#+begin_src vim
:`<,`>B sort
#+end_src

The package extracts the rectangle into a temporary buffer, executes the
command over that buffer, and inserts the result back into the original
rectangle. Surrounding columns are not part of the command's input.
Plain =:'<,'>s/foo/bar/g= is not an equivalent: its range covers whole lines.
The configuration does not remap =:= to =rect-ext-evil-ex=, so enter =B=
and the backtick range explicitly.

**** Edit the rectangle in a separate buffer

| Step | Evil state | Key / command | Command / effect |
|------+------------+---------------+------------------|
| Select | Normal | C-v, then motions | Select the rectangular area to edit. |
| Extract | Visual Block | s n | Run =rect-ext-narrow= to open the rectangle in a separate buffer. |
| Edit | Normal, extracted buffer | :%s/foo/bar/g or :%sort | Replace or sort throughout the extracted buffer. Other editing commands can be used there as well. |
| Apply and return | Normal, extracted buffer | s w | Run =rect-ext-widen= to replace the original rectangle with the edited text and close the extracted buffer. |

Return to Normal state before editing if needed. =s w= is the apply-back
command; native =widen= (=m w=) does not reinsert the rectangle. Saving the
extracted buffer is not the apply-back operation either. After returning,
save the original buffer normally if you want to persist the changes.

**** Limitations and precautions

- Reinsertion splits the edited text on runs of newlines, so empty rows can
  be lost. Avoid these workflows when blank rows must be preserved.
- The Evil =B= command additionally calls =delete-trailing-whitespace= on
  the affected region. This may remove trailing spaces beyond the selected
  columns on affected lines; do not assume whitespace outside the rectangle
  is completely untouched. The =s n= / =s w= workflow does not perform this
  additional cleanup.
- Keep the number of rows unchanged. The implementation replaces the
  original rectangle row by row and does not handle row-count changes robustly.
- Do not edit the original buffer while the extracted buffer is open:
  the package stores numeric positions rather than tracking moving boundaries.
- The extracted buffer is a plain temporary buffer; do not assume the source
  buffer's major mode or buffer-local settings are preserved.
- Use a scratch copy for whitespace-sensitive data. Review the result and
  use undo in the original buffer if necessary.

** Edit an Org source block and return

| Key | Command / effect                                                             |
|-----|------------------------------------------------------------------------------|
| , e | Edit the source block at point in its dedicated buffer (=org-edit-special=). |
| , w | Write the edits back to the Org block and exit (=org-edit-src-exit=).        |
| , q | Discard the edit-buffer changes and exit (=org-edit-src-abort=).             |

=,w= and =,q= are alternatives for finishing the same operation, not
successive steps. Both bindings apply only in Normal state in an active Org
source editing buffer, regardless of its language. Ordinary Emacs Lisp buffers
are unaffected, and =S= and =T= retain their usual Evil behavior.

Cloning is an alternative that creates a copy without a separate paste step.

| , j | Copy the subtree down (=org-metadown=). |
| , k | move the subtree up (=org-metaup=). |
| , l | Copy the subtree under (=org-metaright=). |
| , y | Copy the subtree (=org-copy-subtree=). |
| , d | Cut the subtree (=org-cut-subtree=). |
| , p | Paste the copied or cut subtree (=org-paste-subtree=). |
| , c | Clone the subtree with a time shift (=org-clone-subtree-with-time-shift=). |
| , Y | Copy the URL at point (=ninrod/org-retrieve-url-from-point=). |

** Code folding

Origami is enabled in programming modes and =vimrc-mode=, using ={{{= / =}}}=
markers with nested regions. Marker folds start closed when a buffer is opened.
Ordinary comments and unmarked code are not folded.
Org keeps its existing outline-based folding.

| Evil state | Key | Command / effect |
|------------+-----+------------------|
| Normal | TAB / za | Toggle the code fold at point. |
| Normal | zc / zo | Close / open the code fold at point. |
| Normal | zM / zR | Close / open all code folds. |

* Edição
** Lispyville: edição estrutural de Lisp
*** When this cheat sheet applies

These keys belong to Lispy, integrated with Evil by Lispyville.

They apply when =special= appears in the modeline: Evil is in Insert or Emacs
state, and point is before an opening delimiter, after a closing delimiter,
or an active region puts Lispy in special context.

In this context, letters execute commands instead of inserting text.
In Evil Normal state, use the usual Evil and Lispyville bindings instead.

*** Navigate the structure

| Key   | Action                                                   |
|-------+----------------------------------------------------------|
| j / k | Move to the next / previous expression at the same level. |
| h     | Move outward to the beginning of the parent list.         |
| l     | Move outward to the end of the parent list.               |
| d     | Switch between the beginning and end of the current list. |
| f     | Navigate into a nested list.                              |
| q     | Jump to a visible delimiter using letter labels.          |
| a     | Select a symbol in the list using letter labels.          |
| A     | Move to the beginning of the top-level function.          |

*** Edit the structure

| Key   | Term      | Action                                                |
|-------+-----------+-------------------------------------------------------|
| >     | Slurp     | Pull a neighboring expression into the list.           |
| <     | Barf      | Push an expression out of the list.                    |
| /     | Splice    | Remove the enclosing delimiters, keeping the contents. |
| r     | Raise     | Replace the parent list with the current expression.   |
| w / s | Drag      | Move the expression up / down among its siblings.      |
| c     | Clone     | Duplicate the expression.                             |
| +     | Join      | Join lists.                                           |
| C     | Convolute | Exchange the heads of two enclosing lists.             |

**** Slurp: pull an expression inside

#+BEGIN_SRC emacs-lisp
;; Before
(a b) c
;; After
(a b c)
#+END_SRC

**** Barf: push an expression outside

#+BEGIN_SRC emacs-lisp
;; Before
(a b c)
;; After
(a b) c
#+END_SRC

**** Splice: remove the inner list's wrapping

#+BEGIN_SRC emacs-lisp
;; Before
(a (b c) d)
;; After
(a b c d)
#+END_SRC

**** Raise: keep the selected inner expression

#+BEGIN_SRC emacs-lisp
;; Before, with the inner expression targeted
(foo (bar baz))
;; After
(bar baz)
#+END_SRC

**** Special versus Normal state

In Lispy special, =>= always slurps and =<= always barfs.

In Evil Normal state, the configured =slurp/barf-cp= theme uses these keys
as arrows that move a delimiter. The result depends on whether point is
on an opening or closing delimiter.

| Key | Action                                          |
|-----+-------------------------------------------------|
| e   | Evaluate the expression and display the result.  |
| E   | Evaluate and insert the result into the buffer.  |
| i   | Reindent and normalize the expression.           |

*** Select, copy, and exit

| Key   | Action                                                               |
|-------+----------------------------------------------------------------------|
| m     | Select the list.                                                     |
| v     | With a region, toggle between Lispy and Evil Visual; otherwise mark.  |
| n     | Copy the expression to the kill ring.                                |
| P     | Paste using Lispy's paste command.                                   |
| N / W | Narrow the buffer to the expression / widen it again.                |

| ESC   | Cancel the selection and return to Evil Normal state.               |

The =v= and =ESC= behavior reflects the personal Lispyville configuration
in =boot.org=, rather than unmodified Lispy defaults.

*** Counts

Numbers prefix commands that support repetition:

- =3j=: move forward three expressions.
- =2>=: slurp two expressions.

*** Learn these first

- Navigate: =j=, =k=, =h=, =l=, =d=.
- Edit: =>=, =<=, =/=, =r=, =c=.
- Evaluate and format: =e=, =i=.
- Exit: =ESC=.

From Insert state, =)= normally moves point to the end of the current list,
which is a quick way to reach special context. Check the modeline indicator
before using letter commands.
